# 첫 로비 입장 — 정보요원 한 (2026-10-30)

사용자 PDF `튜툐리얼.pdf`, `튜툐리얼 - 이름 확인.pdf`, `튜툐리얼 - 이름 확인-1.pdf`를 `docs/references/`에 보존했다. 모두 1920×1080으로 렌더링하고 원본 텍스트·그림·색상·좌표를 분석했다. PDF의 Pretendard는 기존 사용자 지시대로 SUITE Variable로 표시한다. **새 PDF의 30일 표기는 사용자가 명시적으로 기존 7일을 유지하도록 답했으므로 화면과 서버 모두 7일이다.**

## 흐름

가입은 로그인 아이디·비밀번호만 받는다. 가입 직후 이전 CityNickname 창을 띄우지 않고 실제 로비에 들어가 아래 안내를 시작한다. 미완료 계정은 다음 로그인 후 1서버에 들어가면 저장한 지점부터 이어간다. Google 신규 계정과 방 초대 URL의 미등록 사용자도 같은 안내로 연결한다. 초대 방 입장 같은 대기 동작은 안내 완료 후 수행한다.

| 저장 단계 | 화면 |
| --- | --- |
| 0 | 일러스트 없이 `??? : 잠깐 시간 괜찮으십니까?` |
| 1 | 한의 원본 일러스트 등장, 자기소개 |
| 2 | 사용자 원문 코드네임 설정 안내 |
| 3 | PDF의 붉은 코드네임 입력창 |
| 4 | 설정한 닉네임을 넣은 원문 환영 대사 |
| 5 | 사용자 원문 크라임 시티 소개 |
| 6~13 | 빠른 입장, 시나리오 선택, 방 만들기/NPC 체험, 내 정보, 채팅, 재화/상점, 공지/음량/준비 중 기능, 마무리 |
| 14 | 안내 완료, 자유로운 로비 이용 |

클릭이나 일반 키 입력으로 한 단계 진행한다. Enter/Space와 Tab 이동도 지원한다. AUTO는 대사 길이에 따른 자동 진행이며 입력 단계에서 정지한다. SKIP은 이름 미설정이면 3단계까지만 이동하고, 이름 설정 후에는 완료한다. 이름 입력 자체는 건너뛸 수 없다. 이름은 Enter 또는 오른쪽 하단 확인 문구 클릭으로 제출한다. ESC는 진행을 지우지 않고 시작 화면으로 돌아간다. 미완성/실패 요청을 성공으로 표시하지 않는다.

이미 닉네임을 정한 기존 계정에는 안내를 강제로 재생하지 않는다. 내 계정의 `로비 튜토리얼 다시보기`로 볼 수 있다. 다시보기는 진행 기록을 쓰지 않고 기존 코드네임을 읽기 전용으로 표시한다. 해당 화면에서 실제 닉네임 변경 API를 호출하지 않는다.

## 원본 배치와 자산

- 실제 현재 로비에 검은 반투명/4px 흐림 레이어를 겹친다. 과거 로비 스크린샷을 배경으로 붙이지 않는다.
- 한은 1920×1080 투명 레이어에 원래 좌표 그대로 있다. 실제 내용 범위는 (453,56)~(1255,1080), 붉은 패턴 그림자도 원본이다. 0단계에서는 숨기며 이후 부드럽게 나타난다.
- 화자 y=829, 크기 35px. 본문 y=903, 크기 32px/행간 44px. 하단 진행 문구 우측 46px, y=1021, 25px.
- AUTO (1564,32), SKIP (1747,32). 두 화살표는 원본 로고의 크롭·반전이다.
- 이름 입력 장식은 원본 사선 패널, 그림자, 좌우 점무늬, 시계와 바늘까지 추출했다. 패널 전면 (386,486)~(1538,597). 입력은 (406,492,1108,94), 안내문 y=643/681에 대응한다.
- 오류 캡슐은 (563,737,794,99), 붉은 선 #ad092b, 글자 30px. 중복 문구는 원문의 `이런.. 중복된 코드네임입니다. 다시 한번 부탁드립니다.`다. 욕설/형식 오류도 같은 위치에서 안내한다. 오류 후 입력 포커스를 복구한다.
- `public/assets/tutorial/manifest.json`은 PDF 원본 이미지 출처를 기록한다. `han.png`, `codename-decor.png`는 PDF의 필요한 그래픽 그룹만 추출하고 최상위 soft mask까지 유지한 투명 합성 자산이다. 글자·과거 로비를 포함하지 않는다. 원본 PDF의 회색 blur backing 이미지만 사용하면 형태가 깨지므로 이 두 자산을 사용한다.
- 후반 안내는 해당 로비 영역을 옅은 붉은 외곽선으로 표시한다. 캔버스를 통째로 비례 축소하며 패널을 재배치하지 않는다. 동작 줄이기와 포커스 제한/복귀를 지원한다.

## 서버와 이전 DB

`users.tutorial_step`은 기본값 0이다. `GET /api/tutorial`은 본인 진행/이름 설정 여부만 읽고 `POST /api/tutorial {step}`은 다음 단계, 이름 단계로 건너뛰기, 이름 설정 후 완료만 허용한다. 세션·CSRF·단계·예상 밖 필드를 검사하고 조건부 UPDATE로 진행 충돌을 보호한다. 닉네임 최초 설정은 기존 검증(정규화/2~12자/한글·영문·숫자/금칙어/중복)을 쓰며 이름 저장과 동시에 4단계로 이동한다. 설정 전 방 생성/참여·채팅 쓰기는 여전히 서버에서 차단한다. 기존 닉네임 변경 제한은 7일이다.

원본 DB에는 **0009_slippery_nextwave.sql만** 추가 적용했다. 새 컬럼을 추가하고 당시 이미 닉네임을 설정한 계정은 14단계로 표시했다. 기존 닉네임·프로필·재화·게임 기록은 바꾸지 않았다. 이미 데이터가 있는 DB에 db:init 또는 과거 마이그레이션을 재적용하지 않는다.

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config wrangler.local.json --persist-to .wrangler/state --file drizzle/0009_slippery_nextwave.sql
npm run db:check
```

0008까지 있는 백업에만 이 누락 파일을 한 번 적용한다. 새 빈 DB는 db:init으로 0000~0009를 적용한다. 기존 ZIP/SQL 백업은 자동으로 갱신되지 않는다.
