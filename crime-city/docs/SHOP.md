# 정보 상인단 상점 — 2026-10-27

## 원본과 화면

사용자 PDF 7개를 `docs/references/`에 보존했다. 모두 1920×1080 한 페이지이며 Poppler로 렌더링해 실제 구현과 대조했다. PDF의 Pretendard는 사용자 지시대로 SUITE Variable로 표시한다. 상점은 로비와 별개의 원본 붉은 팔레트를 유지한다.

## 상품과 임시 규칙

문서함 I은 원본 구성이다. II·III는 “I와 비슷하게 더 풍족하게”라는 사용자 허용에 따라 임시로 늘렸다. 세 상품은 각각 계정당 2회이며 첫 상점 접근부터 22일 판매로 가정했다. 원본 4번째 I 타일은 같은 상품/구매 제한을 공유하고 삽화만 원본처럼 다르다.

| 상품 | 가격 | 구성 |
| --- | ---: | --- |
| 문서함 I | 5,900P | 5,900P 교환권 1, 입주민 테두리 1, 입주민 명찰 1, 리스트업 차트 5 |
| 문서함 II | 12,400P | 12,400P 교환권 1, 테두리 1, 명찰 1, 리스트업 차트 10, 파트너 차트 5, 3일 부스트 1 |
| 문서함 III | 29,800P | 29,800P 교환권 1, 테두리 1, 명찰 1, 리스트업 차트 25, 파트너 차트 10, 3일 부스트 3, 닉네임 컬러 박스 3, 랜덤 포인트 박스 3 |

- 무료 3칸은 각 1회. 한국 시간 매일 00:00에 구성과 구매 가능 횟수를 갱신한다. 임시 5종 풀(2일 부스트/닉네임 컬러 박스/랜덤 포인트 박스/리스트업 차트/파트너 차트)에서 날짜·갱신 횟수로 순환한다. 무작위 상품 추첨 기능은 아니다.
- 즉시 초기화는 **1,500P**. 무료 3칸을 교체하고 수령 횟수를 복구한다. 월간·문서함 제한에는 영향을 주지 않는다. 초기 5,000P 제안은 폐기했다.
- 포인트샵: 3일 부스트 12,000P, 파트너 차트 4,500P, 리스트업 차트 3,500P, 방장 부스트 5,900P. 차트 2종만 각각 월 5회다. 월간 제한은 한국 시간 매월 1일 00:00 갱신한다.
- KRW 상품과 월간 티켓은 **결제 준비 중**. 결제 버튼을 비활성화하고 서버도 거부한다. 실제 청구·토큰 충전·첫 충전 두 배·티켓 일일 지급은 없다. 원본의 마지막 가려진 코인 수량은 임의로 확정하지 않고 일반 상품명만 표시한다. 원본의 `2,9800` 표기는 29,800원으로 해석했다.
- 구매한 아이템은 인벤토리에 저장된다. 교환권 사용은 해당 포인트를 지급하고, 임시 랜덤 포인트 박스는 100~500P를 지급한다. 부스트/차트/닉네임 꾸미기/입주민 외형의 실제 적용 효과는 아직 없으며 인벤토리 설명에 준비 중임을 명시했다.

## 서버와 데이터

`GET /api/shop`, `POST /api/shop/intro {}`, `POST /api/shop/purchase {requestId,revision,productId,offerKey}`, `POST /api/shop/refresh {requestId,revision,dailyKey}`.

로그인/닉네임/CSRF 검사를 거친 본인 데이터만 접근한다. 가격·보상·날짜·횟수는 서버에서 결정한다. D1 batch에서 주문 기록·포인트 차감·인벤토리 지급·상점 횟수를 함께 반영한다. 상점/인벤토리 revision과 서버 시도 ID를 검사하며 요청 UUID 재전송은 기존 주문으로 응답한다. 중복 클릭·다른 탭 경쟁은 이중 차감/이중 지급하지 않는다. 인벤토리 교환권도 revision과 mutationId로 지급을 보호한다.

추가 테이블은 `player_shop_states`, `shop_orders`. 원본 로컬 DB에는 **0008_eminent_scalphunter.sql만** 추가 적용했다. 예전 백업은 자동 갱신되지 않는다. 0007까지 있는 기존 DB에서 아래 누락 파일만 한 번 적용한다. 초기 마이그레이션 재적용이나 db:init으로 실제 DB를 덮어쓰지 않는다.

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config wrangler.local.json --persist-to .wrangler/state --file drizzle/0008_eminent_scalphunter.sql
npm run db:check
```

새 빈 DB만 db:init으로 0000~0008을 적용한다. 로컬 백업 검사/내보내기에도 두 테이블을 추가했다. 주문/개인 인벤토리를 공개 프로필로 반환하지 않는다.
