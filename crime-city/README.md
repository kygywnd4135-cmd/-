# Crime City — 온라인 머더 미스터리

시작 화면 → 아이디 가입·로그인 → (신규) 레이븐의 첫 입장 스토리에서 닉네임 설정 → 로비 → 방 생성·입장 → 6인 사건 진행.

다른 계정/AI/PC에서 이어갈 때는 먼저 [현재 인수인계](docs/HANDOFF.md)를 읽습니다. 사용자 원본은 `docs/references/`, 최근 화면은 로컬의 `docs/screenshots/`에 있습니다. 공유용 소스 ZIP에서는 계정 정보가 보일 수 있는 화면 캡처를 제외합니다. `AGENTS.md`와 `CLAUDE.md`에 작업 규칙을 기록했습니다. 계정·채팅·업로드 사진이 들어 있는 비공개 SQL 백업은 소스/GitHub와 분리해 보관합니다. Claude 연결은 [Claude 이어하기 안내](docs/CLAUDE-CONTINUE.md)를 참고하세요.

## 화면과 조작

- 로비는 다크 모드만 제공합니다. 일반 UI는 자체 제공 SUITE Variable, 레벨업 제목·숫자는 기존 빛의 계승자입니다.
- 시작 메뉴는 ↑·↓로 선택하고 Enter 또는 클릭으로 실행합니다. 비선택 메뉴는 회색입니다.
- 로그인 전에는 계정 카드가 ‘로그인 / 회원가입’으로 바뀝니다.
- 친구와 함께하기·설정·시작 화면의 공지·확성기는 비공개입니다.
- 사용자 제공 도시 배경과 Crime City 로고, 임시 아바타와 배너를 사용합니다. 메뉴·배경·전환·버튼·채팅 효과는 동작 줄이기 설정을 따릅니다.
- 우측 상단에는 넓어진 보유 포인트 영역, 상점·이벤트 아이콘, 배경 음악·효과음 조절과 설정 표시가 있습니다. 초기에는 음소거입니다.

## 메인 로비와 화면 모드

Frame 310의 B안 배치만 사용합니다. 왼쪽 상단은 넓은 2열 방 목록, 하단은 버튼·프로필·배너·공지, 오른쪽은 전체 채팅입니다. 원본 1920×1080 이미지의 패널 좌표와 외곽 크기를 고정했습니다. 작은 창에서는 재배치 없이 전체를 비례 축소합니다.

화이트 모드와 모드 선택 버튼은 제거했습니다. 시작 화면은 원본 이미지의 색상을 유지합니다. 상점 아이콘은 정보 상인단을 엽니다. 폭죽 아이콘은 이벤트 창을 엽니다. 현재 이벤트 내용은 비어 있으며 이벤트 창은 X·ESC로 닫습니다. 접속 인원 표시는 제공하지 않습니다.

기존 통합 프로필 편집창은 삭제했습니다. 칭호는 내 정보의 목록에서 즉시 선택·저장하며, 자기소개는 우측 하단 연필 아이콘으로 바로 편집합니다. 내 프로필 설정에서 이미지·테두리를 선택합니다. 독립 업적 확인은 준비 중입니다. 인벤토리는 초기 임시 아이템 8개와 실제 구매한 상품을 표시하며 검색/정렬, 장착/해제, 삭제 잠금, 삭제 확인과 서버 저장을 지원합니다. 탭은 ALL → 소비 → 기타 → 이벤트입니다. 게임 일러스트와 부스트·꾸미기 아이템의 실제 효과는 후속 작업입니다. 오른쪽 채팅은 1서버 전체 채팅입니다. 보유 포인트는 서버 수치이며 상점 구매와 교환권 사용을 연결했습니다.

## 정보 상인단 상점

사용자 PDF 7개의 원본 삽화·로고·상품 이미지와 1920×1080 배치를 사용합니다. 첫 입장 대화 → 메인 데이터샵 / 포인트샵 / 프리머시샵 → 상품 상세 → 구매 확인 → 완료 알림 순서입니다. 목록은 가로로 드래그할 수 있으며 빈 상품 그림은 공백입니다.

포인트 구매 시 서버에서 잔액 차감·인벤토리 지급·구매 제한을 함께 저장합니다. 데일리 무료 3칸은 한국 시간 00:00, 월간 제한은 매월 1일 00:00에 갱신됩니다. 즉시 초기화는 1,500포인트입니다. 문서함 II·III는 사용자가 허용한 임시 구성입니다. KRW 상품은 결제 준비 중이며 돈을 청구하거나 토큰을 지급하지 않습니다. [상세 규칙과 원본 좌표](docs/SHOP.md)를 확인하세요.

## 상대방 프로필 보기

전체 채팅에서 다른 사람의 프로필 이미지를 누르면 Frame 346에 맞춘 현재 프로필을 조회합니다. 내 확대 프로필(Frame 345)과 같은 968×604 레이아웃이며 아바타·테두리·칭호·닉네임·레벨·클리어 수·보유 포인트·자기소개·대표 업적·명예 별을 보여줍니다. 캐릭터 일러스트 영역은 공백입니다. 로비와 같은 다크 팔레트를 사용하고 X·ESC 또는 바깥 클릭으로 닫습니다. 친구 요청 버튼은 요청을 서버에 저장하며, 이미 요청을 보냈거나 친구인 상대에게는 중복 확인창을 표시합니다. 상대방 업적은 읽기 전용입니다. 내 창에서는 보유한 대표 업적을 선택·저장할 수 있습니다. 명예 투표와 스킨 변경은 아직 제공하지 않습니다.

공개 조회 API는 로그인과 닉네임 설정을 확인하며 공개 필드만 반환합니다. 로그인 아이디·인증정보·게임 비밀은 포함하지 않습니다. 프로필은 채팅 작성 시점의 복사본 대신 현재 저장값을 읽습니다.

## 자기소개 편집

내 정보의 자기소개란 우측 하단 연필 아이콘을 누르면 같은 칸에서 편집합니다. 최대 180자와 줄바꿈을 지원하고, 저장·취소 버튼 및 글자 수를 표시합니다. Ctrl+Enter로 저장하고 ESC로 취소할 수 있습니다. 취소하면 원래 내용으로 복귀하고 저장에 실패하면 편집 내용을 유지합니다. 자기소개 전용 API가 해당 필드만 저장하므로 칭호 등 다른 정보는 유지합니다. ‘프로필 테두리 변경’ 버튼 문구는 ‘업적 확인하기’로 변경했으며 업적 화면은 준비 중입니다.

## 보유 칭호 선택

내 정보의 칭호를 누르면 같은 칸 안에서 목록이 펼쳐집니다. 현재 적용 중인 항목은 ‘(적용중)’으로 표시하고, 다른 항목을 선택하면 별도 확인 없이 서버에 저장합니다. 목록은 내부 스크롤을 사용하며 칸을 넘는 항목은 휠로 이동합니다. ESC 또는 바깥 클릭으로 닫으며 방향키·Home·End로 항목을 이동할 수 있습니다.

현재 보유 목록은 기존 프로토타입의 세 기본 칭호(뉴비 머미러, 신중한 관찰자, 밤의 기록자)입니다. 서버가 같은 목록으로 선택 권한을 확인합니다. 칭호 전용 저장은 다른 프로필 정보를 변경하지 않습니다.

## 계정과 닉네임

아이디·비밀번호로 계정을 만든 다음 첫 입장 스토리에서 레이븐이 이름을 물을 때 닉네임(코드네임)을 정합니다. 아이디는 영문·숫자·밑줄 4~20자이며 로그인에만 사용합니다. 기존 계정은 마이그레이션 시점의 닉네임을 고정 로그인 아이디로 보존합니다. 닉네임을 변경해도 로그인 아이디는 바뀌지 않습니다. 신규 Google 계정도 닉네임 설정 단계를 거칩니다.

닉네임은 2~12자의 문자·숫자만 허용하며 공백과 특수문자는 사용할 수 없습니다. 클라이언트와 서버가 같은 정규화·금칙어 규칙을 사용합니다. 금칙어는 명시적 목록으로 관리하며 모든 변형을 자동 판별하는 시스템은 아닙니다. 자신의 현재 닉네임과 다른 계정의 닉네임은 중복 안내를 표시합니다.

메인 로비의 닉네임 변경은 Frame 328/329 및 세 번째 와이어프레임의 전용 창을 사용합니다. 현재 다크·화이트 모드에 맞게 표시하고 X 또는 ESC로 닫습니다. 오류창의 확인·ESC는 입력창으로 돌아갑니다. 성공 시 상단에 ‘닉네임 변경 완료’ 알림을 표시합니다. 등록·변경 후 7일 동안 다시 변경할 수 없으며 참여 중인 사건이 있으면 변경할 수 없습니다. 서버의 조건부 쓰기와 고유 제약으로 동시 요청도 검증합니다.

닉네임 설정 전에는 방 생성·입장·프로필 변경·채팅 작성을 차단합니다. 가입을 취소해도 로그인 계정은 유지되며 다음 로그인이나 서버 입장 시 닉네임 설정을 이어갑니다.

## Google 로그인 준비

Google Cloud 설정이 없는 상태로 제작했습니다. 버튼은 ‘연결 준비 중’으로 표시합니다.

OAuth 코드 교환, PKCE, 만료·일회성 state 검증, HttpOnly 쿠키와 Google 계정 연결을 구현했습니다. 실제 Google 로그인은 다음 설정을 추가한 후 검증해야 합니다.

1. Google Cloud에 웹 애플리케이션 OAuth 클라이언트를 만듭니다.
2. 승인된 리디렉션 URI: `http://127.0.0.1:5173/api/auth/google/callback`. 배포 시 실제 도메인을 등록합니다.
3. `.env.example`을 참고하여 무시되는 로컬 `.dev.vars` 또는 호스팅 런타임 비밀 설정에 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`을 추가합니다. `GOOGLE_REDIRECT_URI`는 선택 사항입니다.
4. 서버를 재시작합니다. 설정이 확인되면 Google 버튼이 실제 인증으로 이어집니다.

인증 정보는 소스·클라이언트 코드에 넣지 않습니다. Google 고유 subject로 계정을 연결하고 이메일만으로 기존 계정과 병합하지 않습니다.

## 실행

Node.js 24 LTS와 npm을 권장합니다(최소 Node.js 22.13). 아래는 계정이 없는 새 DB로 시작하는 경우입니다.

```sh
npm ci
npm run db:init
npm run dev
```

`db:init`은 빈 DB에만 0000~0009를 순서대로 적용합니다. 기존 데이터가 있으면 거부합니다. 기존 계정·사진·채팅을 복원하려면 새 프로젝트 폴더에서 `db:init` 대신 `npm run db:restore -- "백업 SQL의 실제 경로"`를 실행합니다. 초기화와 복원을 같은 DB에 모두 실행하지 않습니다. `npm run db:check`로 검사하고 `npm run db:export -- "새 백업 SQL 경로"`로 별도 백업합니다. 미리보기: http://127.0.0.1:5173/. 같은 브라우저 프로필의 탭은 로그인 세션을 공유합니다.

## 검증

개발 서버 실행 후 `npm run check`, `npm run test:smoke`, `node scripts/city-smoke.mjs`, `node scripts/nickname-smoke.mjs --fixtures`, `node scripts/title-smoke.mjs`, `node scripts/bio-smoke.mjs`, `node scripts/public-profile-smoke.mjs`를 실행합니다. 검증은 로컬 주소만 허용하고 자체 테스트 계정을 만듭니다.

최근 공개 프로필 검증은 73개, 내 확대 프로필은 `node scripts/expanded-profile-smoke.mjs`로 67개를 확인했습니다. 명예 DB fixture 검증을 추가하면 수가 달라집니다. 사건·로비·계정·칭호·자기소개·이미지 검증도 각각의 스크립트로 제공합니다. 새 환경에서는 관련 검증을 다시 실행합니다.

인벤토리 검증: `node scripts/inventory-smoke.mjs`. 예전 SQL 백업에 0005 테이블이 없는 경우 `docs/HANDOFF.md`의 누락된 마이그레이션 적용 절차를 따라주세요.

내 프로필 확대창은 로비의 다크/화이트 모드와 무관하게 기존 다크 색상으로 통일했습니다. 버튼 글자의 드래그 선택은 막고, 채팅·확성기·입력칸의 선택과 복사는 유지합니다.

친구 요청 검증: `node scripts/friends-smoke.mjs --fixtures`. 친구 수락/거절과 친구 목록 화면은 후속 구현 대상입니다. 이전 DB의 누락된 0006 적용은 `docs/HANDOFF.md`를 참고하세요.


첫 입장 스토리: 신규 가입 후 암전 → 레이븐과의 대화(스토리1·2, Figma) → 로비. 아무 키로 진행, SKIP은 확인창 후 건너뜀. 대화창 레이아웃은 이후 스토리에도 재사용합니다. 자세한 내용은 docs/HANDOFF.md.
